## 已验证

- API 101 模块被框架识别，钱包主进程成功安装 24 个图片入口 hook。
- 发现 3 个当前钱包加载的卡面来源，并从卡片控件取得显示名称。
- 系统文件选择器读取一张原创测试 PNG。
- 裁剪区自动滚入视野，缩放滑块和拖动可操作。
- 精简界面使用独立裁剪页和固定底部操作栏；三张短名称卡面可在同一屏显示。
- 缩放到 2.0 倍并拖动后，切到桌面再返回，裁剪区域像素比较完全一致。
- 取消编辑后回到主页，换图与查看钱包按钮保持可用；设置页系统返回手势正常。
- 保存 16:10 自定义卡面后，钱包卡片实际显示新图片。
- 在模块中确认恢复默认后，该卡片恢复原图。
- 钱包能够读取只读图片 Provider；普通 ADB shell 调用被 UID 校验拒绝。
- 单元测试 7 项通过，覆盖图片来源边界和方法签名筛选。
- `assembleDebug`、`lintDebug` 通过，lint 无 error。

## 限制

- 未验证其他手机、钱包版本、系统 OTA、设备完整重启后的行为。
- 未验证银行卡页面、真实付款或实体门禁刷卡；模块不处理这些权限和凭据。
- 保存中的 Activity 重建边界经代码复核修正为进程级互斥，尚未做可靠的保存中旋转压力测试。
- 规则以原始图片来源为单位；钱包共用同一张原始图片时，会共用该替换规则。
- 首个 APK 为调试签名的实验构建。不同签名构建之间不能直接覆盖安装；签名密钥不在仓库中。
- CI 构建产物用于开发验证；请从 Releases 获取相同发布者提供的更新。

## 构建复现

```bash
python scripts/build.py --jdk /path/to/jdk-17 --sdk /path/to/android-sdk
```

脚本执行单元测试、Debug 构建和 lint，将 APK 与报告放到 `dist/`。CI 在 Linux 上运行相同 Gradle 任务。
